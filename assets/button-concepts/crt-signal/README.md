# CRT Signal button concept

Review-only assets generated by `python tools/design_crt_buttons.py`.
The generator does not modify the production PNG, embedded header, or ELF.

The current runtime combines glowing colored face symbols, Kenney shoulder and
stick outlines, and smaller original NHDDL Start/Select artwork. The face
symbols are visibly softer than the other controls; Start/Select are relatively
dim. The runtime draws all controller artwork with a neutral tint, so contrast
must come from the assets themselves.

This concept keeps familiar shapes and colors, using 2.8px face strokes with
2px bright colored cores and only a restrained 0.65px halo. Shoulders use a
chamfered frame; stick presses use an octagonal ring. Labels use 2px bitmap
strokes. Start remains a triangle and Select remains a horizontal bar. D-pad
arrows have separate silhouettes. There are no baked scanlines, animated effects,
or isolated white specular lines.

The supplied 128x128 `icons.png` retains the runtime's exact icon rectangles:
26x26 for face, shoulder, stick, and D-pad controls; 22x12 for Start/Select.
The existing Enabled indicator is copied unchanged. An eventual integration
should use `nhddl/include/ui/icons.h`; the older header under
`nhddl/res/gfx/icons/icons.h` contains obsolete rectangles.

`comparison.png` shows the actual before/after pixels at 2x nearest enlargement.
The conversation preview also supports native-size inspection and optional
edge softening. Softening is only a visual approximation, not a model of
interlaced fields, composite video, phosphor response, or bloom.

Design guidance: [Microsoft: Designing for the TV Display](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/windows-media-center-sdk/ms813081%28v%3Dmsdn.10%29)
recommends lines at least two pixels wide for interlaced displays. That informs
the proposed strokes; it does not prove this set is flicker-free on a PS2 CRT.

Before adopting, rebuild with the emulator script and inspect the Options,
library, and file-manager prompt bars in portable PCSX2. Then check on a real
CRT in both supported interlaced modes, especially shoulder-label counters,
red/blue symbol visibility, and Start/Select brightness. Keep the current UI
layout and view transitions intact.
